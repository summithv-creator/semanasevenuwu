MISIÓN 01 · CONVERSIÓN

¿PARA QUÉ SIRVE TO_NUMBER?

FUNCIÓN ELEGIDA: TO_NUMBER

TO_NUMBER convierte un texto que contiene una cantidad numérica en un número con el que Oracle SQL puede hacer cálculos.

💎 Ejemplo de Minecraft: si los 25 diamantes de Steve están guardados como texto ('25'), esta función permite convertirlos a número para sumar, restar o calcular el valor de sus minerales.

💚 Mi opinión

Yo usaría TO_NUMBER en un servidor de Minecraft con una economía basada en minerales. Por ejemplo, para convertir los diamantes registrados como texto en cantidades numéricas y calcular cuánto dinero gana cada jugador al venderlos. Me parece útil porque así los cálculos se hacen con el tipo de dato correcto.

TERMINAL / ORACLE SQL 
SELECT TO_NUMBER('25') AS diamantes
FROM DUAL;

Resultado: 25 como número, no como texto. DUAL es una tabla especial de Oracle para probar expresiones.

📝 '25' = texto💎 25 = número
MISIÓN 02 · CONDICIONALES

CLASIFICAR CON CASE

CASE WHEN ... THEN ... ELSE

Con CASE clasificamos a los jugadores por la cantidad de diamantes que han encontrado. Oracle revisa las condiciones en orden y devuelve la primera que se cumple.

💎 64+ → Experto💎 16+ → Minero🪨 Menos → Novato
CLASIFICADOR DE MINEROS 
SELECT nombre_jugador, diamantes,
       CASE
         WHEN diamantes >= 64 THEN 'Experto'
         WHEN diamantes >= 16 THEN 'Minero'
         ELSE 'Novato'
       END AS rango_minero
FROM jugadores;
Tabla ficticia: jugadores(nombre_jugador, diamantes).
MISIÓN 03 · DECODIFICAR

TRADUCIR CON DECODE

DECODE

DECODE compara un valor con varias opciones exactas. Sirve, por ejemplo, para convertir un código de bioma en una descripción entendible. A diferencia de CASE, es más cómodo para comparaciones simples de igualdad.

🌳 F → Bosque🏜️ D → Desierto❄️ N → Nieve
MAPA DE BIOMAS 
SELECT nombre_zona,
       DECODE(codigo_bioma,
              'F', 'Bosque',
              'D', 'Desierto',
              'N', 'Nieve',
              'Desconocido') AS bioma
FROM zonas;
Tabla ficticia: zonas(nombre_zona, codigo_bioma).
MISIÓN 04 · CASILLAS VACÍAS

MANEJAR NULL

NVL · NVL2

NULL significa que no hay un valor registrado; no es lo mismo que cero. NVL reemplaza ese NULL por otro valor. NVL2 elige un resultado si el dato existe y otro si está vacío.

📦 Sin registro → 0🛡️ Equipo → Sí / No
ESTADO DEL JUGADOR 
SELECT nombre_jugador,
       NVL(diamantes, 0) AS diamantes,
       NVL2(equipo_id,
            'Con equipo',
            'Sin equipo') AS estado_equipo
FROM jugadores;
NVL se usa aquí para mostrar 0 cuando el número de diamantes es desconocido o no registrado; esa decisión depende de la lógica del sistema.
MISIÓN 05 · ELEGIR Y COMPARAR

COALESCE Y NULLIF

COALESCE · NULLIF

COALESCE devuelve el primer valor que no sea NULL, ideal si buscamos una herramienta alternativa. NULLIF devuelve NULL si dos valores son iguales; ayuda, por ejemplo, a evitar divisiones entre cero.

⛏️ Pico principal → Reserva🎯 Evitar / 0
INVENTARIO INTELIGENTE 
SELECT nombre_jugador,
       COALESCE(pico_principal,
                pico_reserva,
                'Sin pico') AS herramienta,
       bloques_rotos /
         NULLIF(minutos_jugados, 0)
         AS bloques_por_minuto
FROM estadisticas;
Si minutos_jugados es 0, NULLIF devuelve NULL y la división no genera un error por dividir entre cero.
